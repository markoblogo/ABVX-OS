# ABVX Broker macOS Threat Boundary V1

The current boundary is a local Unix socket (`0600`) inside an owner-only directory (`0700`), with state files created `0600`, OS peer UID inspection, explicit request schema, owner approval and scoped capability policy. This protects against other ordinary user accounts and accidental unapproved API operations. It does not isolate hostile code running as the same owner. That code can read or rewrite the JSON capability/request/audit files, connect to the socket, run the CLI, invoke the Keychain helper, or manipulate the owner session. POSIX mode bits do not protect one process from another with the same UID.

The current broker is Python; its helper returns the secret on an internal pipe. The socket/CLI deliberately has no secret-get operation. The internal pipe is still a same-user process boundary, not a secret isolation boundary. An agent that already inherits `OPENAI_API_KEY` can use that environment value independently of the broker. Only the variable name's presence was checked in this gate; no value was read.

Accepted for synthetic pilot: same-user local compromise is outside the enforceable boundary; policy controls honest clients and ordinary mistakes. Not accepted for real import: direct invocation of the raw-get helper is an ordinary same-user path, not merely a hypothetical full compromise. A protected service account or a policy-enforcing helper with OS-protected install/state is needed before asserting stronger isolation. No claims of protection from a malicious owner process, root, Keychain compromise, or deceptive owner approval are made.
