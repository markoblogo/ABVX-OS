# ABVX Broker Keychain Hardening V1

**Status: REVIEW.** A synthetic `SecItem` probe passed add, read, update and delete in an isolated temporary file-based Keychain (`OSStatus 0` for read/update/delete). The probe uses `kSecUseKeychain` for add and `kSecMatchSearchList` for lookup, resolving the earlier isolated-keychain lookup failure. It printed status codes only, deleted its synthetic item, and the temporary Keychain was removed. The probe still needs deprecated `SecKeychainOpen` to target the isolated file-based test Keychain. The production helper was not switched to `SecItem` or tested against the login Keychain.

Apple recommends `kSecUseDataProtectionKeychain` for new items, but its access groups depend on signing entitlements; this prototype uses a file-based Keychain for the isolated test. See [TN3137](https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains), [kSecUseDataProtectionKeychain](https://developer.apple.com/documentation/security/ksecusedataprotectionkeychain), [kSecMatchSearchList](https://developer.apple.com/documentation/security/ksecmatchsearchlist), and [kSecAttrAccess](https://developer.apple.com/documentation/security/ksecattraccess).

The live helper remains an unsigned, same-user writable executable built from source on demand. Its `get` action returns the value over stdout to Python. Another owner-UID process could invoke it directly and potentially receive the item after Keychain authorization. A signature or trusted-app ACL applied to that same directly invokable binary would not fix this interface. No real item or login-Keychain ACL was inspected or modified.

Future Keychain access should be inside a policy-enforcing, stable executable with protected installation/state; test the login/default Keychain with synthetic data, first access, restart, rebuild, unintended caller, and upgrade behavior before import. Ad-hoc signing is only an integrity marker for a given binary and does not establish a protected owner/Team ID. Developer ID/Team ID could support stable requirements if available, but is not assumed or purchased here.
