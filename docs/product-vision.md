# Product vision

ABVX-OS is not primarily:

- a coding-agent manager;
- a task manager;
- a repository dashboard.

ABVX-OS is a Personal Operating System / Personal Operator.

Its intended role is to:

- receive arbitrary inputs;
- understand them in portfolio context;
- find opportunities;
- reduce human attention cost;
- execute safely behind policy and approval;
- support revenue generation;
- coordinate media and distribution;
- use Cortex knowledge with explicit boundaries;
- coordinate project development as one subsystem;
- learn from outcomes through evidence.

Development Ops is only one subsystem inside that larger system.

The platform should therefore be judged less by how many internal tools it can build and more by whether it improves:

- opportunity creation;
- economic output;
- execution leverage;
- attention saved;
- safe reuse of knowledge and donor capabilities.

ABVX-OS should remain local-first, evidence-first, donor-first, and bounded by explicit trust, approval, and cost rules.
