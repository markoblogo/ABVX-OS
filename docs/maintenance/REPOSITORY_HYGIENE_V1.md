# Repository hygiene and release checks

The public repository distributes reusable code, schemas, operating contracts, generic documentation and synthetic regression fixtures. The owner workspace also contains private operational material. A request to commit accumulated development does not make manuscripts, retained retailer observations, account inventories, publication packets, source corpora or recovery snapshots public release inputs.

## Review order

1. Run `./bin/maintain inspect`; preserve the path/hash manifest locally. It classifies files but does not delete, sanitize contents or grant approval.
2. Refresh remote references and prepare a task branch from current `origin/main`. A divergent personal branch must not be pushed wholesale: it can contain private historical commits. Carry reviewed code and documentation across while preserving current remote fixes.
3. Update owning documentation, then run dependency, contract, regression, isolated-book, whitespace and staged-file checks. Review executable/security boundaries and retain unavailable native integration checks explicitly.
4. Scan exactly the staged public tree for credential patterns, private source material, symlinks, oversized blobs and unsupported binaries. Synthetic credential canaries must remain identifiable as test data. No actual credential value may be printed in a report.
5. Compare protected local hashes, commit the reviewed tree, push the task branch, and verify the remote SHA. A branch push is not a merge, deployment, publication or live workflow validation.

## Retention and optimization

Use existing `.gitignore` rules and an explicit source/export manifest. Keep canonical evidence, paid outcomes, original manuscripts and recovery receipts in place. Do not prune `.tmp/multi-market-radar/learning` or other retained history merely because it is ignored. No history rewrite or automatic Git garbage collection is part of this procedure.

Ignored paths that were already tracked remain in historical commits. Ignoring them prevents accidental additions; it does not remove prior disclosure. Deletion, history rewriting and credential rotation require separately scoped work if a real exposure is confirmed.

Place large review worktrees and test environments on the repository volume when the system disk is constrained. Use one normal validation run and focused reruns after a failure or fix. Native Keychain tests require the explicit opt-in in the development guide; test counts, skipped integrations, branch readiness and operational readiness remain separate.
