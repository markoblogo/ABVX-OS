# ABVX publication learning cycle: v2 timing, compatible v1 closeout

Owner-approved NORMAL thin adapter within OS ↔ Cortex scope. Reuses content approval, project checks and private admission/retrieval. No scheduler, new model or publication executor.

## Working cycle

1. Immediately after an explicit publish command, before formatting/intake, run `publication begin --run <unique-cycle-id> --item <unique-intake-id>`; repeat `--item` for a pool (1–20). The current UTC time is the first-work-after-command start; no historical chat timestamp is inferred. Material receipt while the owner is still assembling a pool is not authorization to start publication. Then `scripts/prepare_abvx_publication.py` prepares supplied native Markdown. A ready Writing or Working Story intake automatically starts an ignored `.tmp/publication-learning/<id>/session.json`. Tracked test fixtures are SYNTHETIC; completed IDs or changed workloads require a new intake ID.
2. Inspect and approve with the existing owner gate. `content publish` emits the project handoff; it does **not** declare production success. Apply, commit, PR and deploy using ABVXsite's own mechanism and permissions.
3. `publication check` invokes the existing site `content:release-check` once, or imports its complete hashed receipt with `--reuse-checks`. This retains content/ecosystem validation, lint, sync/vector tests, build, SEO checks and dependency audit, binding log hashes to the exact site tree, executable modes, unstaged deletions and approval. A changed source tree requires another check.
4. New cycles use `publication complete-cycle --run <cycle-id>` after **all** members are in the same checked, committed production release. It reuses each member’s source/approval/hashed checks, verifies public prose for every page and matches the latest successful Production deployment to the exact clean merge SHA twice. One aggregate observation is exported; member closeout is blocked to prevent correlated duplicate measurements. Legacy `publication complete` checks native source/media, retained check logs, checked tree, HTTPS 200 HTML on `abvx.xyz` without redirects, canonical/title and authored prose. Then it records an immutable outcome and exports the numeric batch. Preview, handoff, merge or Vercel notification alone cannot pass. This verifies visible content, not Google's indexing or the deployed SHA.
5. With `--cortex-root`, completion automatically admits the batch, recalls the same workflow/version and generates a model-free diagnosis. OS independently verifies the return against retained source batches. If Cortex is unavailable, the local outcome/batch stay available for `publication transfer`. Duplicate successful delivery is idempotent. Immutable files are installed atomically; rejected ID reuse preserves the previous item. Only batches cited by the bounded Cortex context are loaded during return validation.

6. Before widening participation to a book phase, `publication verify-first-cycle` reuses exact-tree/log/source verification, independently revalidates the scoped Cortex return, and queries GitHub read-only for the latest Production deployment/status and associated merged site PR. The deployed SHA must exactly match the committed clean checked checkout and the site PR merge commit. It freshly probes approved prose and rejects a concurrent rollout. The ignored `first-cycle.json` binds hashes of normalized selected deployment/status/merge metadata, outcome/source-packet/context/review digests and public HTML digest. Unrelated provider descriptions do not invalidate a retry. Missing, preview, pending, failed, unmerged or wrong-SHA evidence cannot pass. This point-in-time acceptance enables no book hook or business admission. An operator report alone is not a receipt.

The operator/agent performs this closeout during the publishing workflow; the owner does not need to copy telemetry. This covers native Writing articles, video companion articles and Working Stories. RSS-only entries are outside the intake. Books can use reviewed outcomes; their automatic lifecycle hook is a later distinct milestone.

## Operator commands

```sh
./bin/abvx publication begin --run publication-cycle-unique --item publication-unique-id
python scripts/prepare_abvx_publication.py --source /absolute/post.md --id publication-unique-id --asset /absolute/cover.webp=/media/writing/cover.webp
./bin/abvx content inspect publication-unique-id --json
./bin/abvx content approve publication-unique-id
./bin/abvx content publish publication-unique-id
# Apply with the site's existing publisher, then check the final tree.
./bin/abvx publication check --item publication-unique-id --site-root /Volumes/Work/Work/ABVXsite
# Publish through the normal site release flow, wait for production, then close.
./bin/abvx publication complete-cycle --run publication-cycle-unique --site-root /Volumes/Work/Work/ABVXsite --rework-count 0 --cortex-root /Volumes/Work/Work/CortexABV-private
# Retry only the handoff if Cortex failed after the outcome was retained.
./bin/abvx publication transfer --item publication-cycle-unique --cortex-root /Volumes/Work/Work/CortexABV-private
```

The existing v1 `first-cycle.json` remains the separate book-pilot proof; new cycle members are not closed with the legacy verifier. Use the selected Python environment. The commands do not install dependencies. `verify-first-cycle` uses an already authenticated GitHub CLI with deployment/PR read access; it writes only ignored local proof and never triggers a deployment. If GitHub evidence is unavailable, native closeout remains recorded and first-cycle acceptance remains pending. GitHub environment/status reports and matching public content are point-in-time evidence, not continuous domain-alias monitoring. Endpoint reference: [GitHub deployment API](https://docs.github.com/en/rest/deployments/deployments#list-deployments). Supply the actual rework count, not an assumed zero. No unattended harvesting of arbitrary site changes is enabled.

## Measurement and privacy

For new v2 cycles, duration covers the first work immediately after the publish command → verified production, including preparation, checks, PR/CI, deployment and waiting. It is end-to-end latency, not active CPU or agent time. v1 rows continue to mean ready intake → verified production; never mix these definitions or rewrite old evidence. Durable publication sessions use millisecond UTC wall time. Same-process maintenance checks use a monotonic high-resolution clock. Legacy integer observations remain accepted alongside bounded finite fractional seconds; old zero-duration rows are not retroactively corrected.

Owner participation remains UNKNOWN. The owner-selected v2 publication objective is lower elapsed time with no increased rework and all quality/safety gates passing; effort is neither estimated nor zero-filled and is not a publication-latency qualification requirement. The explicit hashed measurement marker, controlled workflow versions and cycle binding are independently validated in OS and Cortex. Older publications and book/maintenance workflows keep their existing effort requirements. A latency result makes no claim about labor or token savings.

The stable workload profile includes surface, check tier, asset count, video presence and actual build mode. Its `workload:` name and hash determine cohort comparability; changing production/log hashes remain provenance. Legacy rows without a profile require identical evidence names **and hashes**. A profile is operational comparability, not proof that arbitrary articles have equal complexity or that one successful run establishes a gain.

Only opaque identifiers, numeric metrics, gate states and evidence hashes enter Cortex. No authored text/media, URL, absolute path, log contents or credentials are exported. Sessions, checks, batches and return receipts stay ignored. Full metrics return READY_FOR_ANALYSIS without invoking a model; missing metrics return a cited diagnosis. Optional model synthesis remains separately invoked and operationally unqualified. No result grants adoption, deletion or publication authority.

## Verification and release scope

Tests cover automatic start, approval/handoff separation, altered-tree and complete-frontmatter rejection, fenced-code compatibility, interruption recovery, bounded source resolution, preview/wrong production text rejection, immutable metrics and idempotent OS → temporary Cortex → OS exchange. First-cycle tests use temporary Git checkouts and mocked deployment/merge, HTML and previously covered closeout/return seams; they cover binding/idempotency and reject mismatches, previews, pending rollouts, concurrent changes and synthetic/uncommitted input. They do not claim a real publication or live provider acceptance. Cross-runtime fixtures never enter the canonical operational ledger.

This small release excludes unreviewed recovered Book Radar, Book Core, psychology and wider maintenance changes from OS PR #2. That recovery remains protected and open for separate review. Cortex PR #4 includes its reviewed ID contract and OS source, with inference, retention, private output and packet-identity boundaries repaired.

## Single publications, pools and sequential trials

- One command/release is one independent cycle. A pool is not N independent successes; shared correction rounds are counted once. Failed/interrupted work keeps its original timer and is reported, never restarted under a fresh ID to improve the result. Do not omit failed attempts from a trial report. No outcome is declared until verification passes; failed attempts retain incomplete evidence and cannot qualify as successful runs.
- Freeze the list of unique intake IDs before work; membership claims prevent reuse in another cycle. Additions belong to a later cycle. Begin retries retain the original timestamp. Changed membership/trial and retroactive starts are rejected.
- Apply all approved members, generate all indexes once, run the full release check once on the complete frozen tree, then import the same receipt for every other member with `publication check --reuse-checks`. Use one PR and one production deployment where possible. Reuse is allowed only for the same tree/log hashes; any source change requires fresh checks. Closeout hashes the common tree twice, while checking every member’s approval and production HTML.
- Compare matching workload profiles: single versus single, or pools with the same count and composition (surface, tier, media count, video flag, build mode). Total cycle latency is primary. Time divided by item count is descriptive only, not independent samples or evidence of equal item complexity.
- Start with `--trial baseline`. Test **one** of `early-input`, `batch-validation`, `reuse-context` per candidate series; these are existing allowlisted techniques, not asserted improvements. `early-input`: validate supplied frontmatter/media before formatting. `batch-validation`: the frozen-pool/shared-check procedure above. `reuse-context`: retrieve only verified workflow-scoped context. Keep the remaining procedure fixed; compare five independent baseline cycles with five separate candidate cycles for a provisional owner-review result. This is a pilot threshold, not statistical proof. Do not accumulate multiple changes in one trial version or compare singles to pools. First results are signals, not measured efficiency claims.

State is private under `.tmp/publication-learning/<cycle-id>/`: `cycle.json`, member claims, `cycle-proof.json`, immutable outcome/packet and independently verified Cortex return. Cortex receives one numeric row plus evidence hashes, never the membership list, prose, URLs or media. No timer is started by an RSS import or a background watcher.

## Trial coverage and recovery (review hardening)

Formal qualification requires a series declared **before any work**, with one intervention and complete baseline/candidate cycle IDs. `publication series-begin --series <id> --change EARLY_INPUT_VALIDATION` takes repeated `--baseline-run` and `--held-out-run` (5–20 each). This creates a private immutable manifest; the agent prepares these opaque IDs, not the owner. Each planned `publication begin` supplies `--series <id>` and the matching `--trial`. Held-out work waits for every baseline cycle to end. The entire baseline must finish strictly before any held-out cycle starts. Standalone observations without a declared series remain useful history but cannot qualify a measured optimization.

An interrupted attempt resumes with the same timer. When it truly fails or is cancelled, use `publication abort-cycle --run <id> --status FAIL|CANCELLED --rework-count <actual> [--cortex-root <path>]`. It retains elapsed time, UNKNOWN effort/gates and a terminal negative outcome. Include every declared cycle in evaluation; missing, failed, cancelled or omitted attempts prevent qualification. Supply the same immutable numeric-only manifest to Cortex `os:evaluate --series <file>` and OS `learning inspect-proposal --series <file>`. Its digest must match every row; candidate lists must equal the complete manifest. No material/member titles or manuscript contents are exported.

Recovery replays a single durable reservation journal while holding the existing local lock before another begin can reserve members. Cycle and intake namespaces cannot overlap. Producer cycle IDs reserve room for the `publication:` packet prefix (maximum 108 characters); the numeric exchange accepts full 120-character opaque run IDs through namespace-aware cycle evidence validation.

A production release must be newer than the cycle start and can be reserved by only one cycle. Both evaluators also reject duplicate deployed-SHA evidence. `batch-validation` requires a pool and exactly matching common check references, log hashes, tree and build mode across members; other trials retain the baseline procedure so the change can be measured. Controlled candidate versions map exactly to their intervention; `publication-v2-baseline` is the baseline only. Publication recall requires `--workflow-version`, and analysis cannot mix versions or legacy/new timing definitions.

Every outcome in the evaluated packet carrying the same series digest must belong to the declared cohorts, including failures/cancellations. Series timestamps must be strictly earlier than every run; equality is not preregistration. Before intake, `abort-cycle` requires explicit `--origin OBSERVED|SYNTHETIC`; with sessions, origin must match their evidence. A terminal failed/cancelled cycle cannot reserve a production release, and altered terminal evidence is rejected before reservation. Both merge and deployment creation must be on/after cycle start; redeploying an older merge cannot create a new publication measurement.
