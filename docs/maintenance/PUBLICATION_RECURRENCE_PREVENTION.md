Cost: CHEAP operator guidance over existing capabilities. Read before formatting a supplied native article. This changes neither publication authority nor the site's content-only boundary. No new service, renderer or publishing lane is introduced.

## Preflight rules

| Known failure | Default prevention | Required evidence |
| --- | --- | --- |
| Numbered recipe steps split into separate lists at blank lines; current site CSS also hides native ordered-list markers | For new numbered procedures, use supported paragraphs with explicit bold labels (`**1.**`, `**2.**`, etc.), as in the existing roe deer note. Preserve every step's wording and order; review formatting before freezing its source hash. A contiguous Markdown list alone does not prove visible numbers. | In the real built page, verify all expected labels are visible and sequential at desktop and mobile widths. Check displayed numbers, not merely the number of `li` nodes. |
| Source Markdown looks correct but the renderer does not implement that feature | Use the existing `illustrations` descriptors with uniquely matching `afterHeading`, captions, dimensions and hashed asset mappings for body images. Do not use unsupported Markdown image syntax or introduce rendering code inside a publication PR. Recheck capabilities when the renderer changes; do not retain obsolete claims that thematic breaks are unsupported. | Source validation plus real image/caption loading and placement in browser QA. |
| Standalone video links remain text because the article surface has not enabled the shared video renderer | Before freezing a multi-video article, inspect the actual surface adapter. Native Writing and Working Stories now enable the existing player. Use labelled standalone HTTPS YouTube links; inline links remain references. Any missing adapter wiring belongs in a separate tested engineering PR. | Render all expected distinct video IDs with descriptive titles, lazy loading and fallback links; verify mobile overflow on the published page. Preserve film subjects and dates separately from business outcomes. |
| External-link metadata uses the wrong field names | Follow the site's actual link schema (`type`, `label`, `url` with an allowed type). If the reference is already a body anchor and needs no separate link strip, retain `links: []`. Do not guess `href` or invent a link type. | Consumer dry-run before writes/build/PR; the requested body link and final approved source remain intact. |
| Review stays Running, says completed with null/wrong SHA or unknown findings, or a correction push still shows the old review | Require a completed review for the exact final head with explicit no-unresolved-findings evidence and no open threads. Long-running review is provider waiting: retain the existing PR/checks/timer and resume bounded read-only readiness checks; do not rebuild or recreate the release. The owner explicitly authorized one `@codex review` retry per stalled owner PR in ABVXsite on 2026-10-24 (current threshold: over 10 minutes). Check for an existing retry before sending. This standing message permission does not authorize a second retry, review suppression, a manual-review merge bypass or releases outside each task's scope; never reuse an older bypass. | Current-head receipt and review-thread inspection before merge. Record review waiting, transport failures and any authorized retry separately from source rework; a resolved correction still needs final-head review. |
| Squash merge cannot fast-forward the original feature branch | After merge, read the provider merge SHA, require a clean checkout and switch to that exact commit (detached is sufficient). Preserve the feature branch; never force-reset unrelated work or create another release to align history. | Local HEAD equals the successful Production merge SHA before production QA and OS closeout. |
| Registry access failure or app restart causes wasted retries and lost timing | Give the dependency audit the required scoped network access. Classify DNS/access failures separately from vulnerability findings. Resume the same cycle, item, PR and readiness journal after interruption. Use fail-fast command sequencing so a failed assertion cannot be followed by commit/push. | Preserve failed attempts and the original cycle start; do not reset wait time or call missing data zero. |

These are operator-enforced checks, not a claim that every case has automatic validation. Existing site validation and browser QA remain authoritative. A future automatic guard or CSS/renderer fix is a separate engineering change with its own tests and review, never mixed into an article PR.
