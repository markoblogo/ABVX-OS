# RN8 learning

RN8 supports the v4 correction: start from an observed book-buying job, not merely a topic or a trigger. A release date can create attention without creating demand for an independent book. A current listing proves supply, not sales. Portfolio assets may lower delivery cost only after external demand is supported.

The larger correction came from authenticated first-party data. The user-reported phrase “zero sales across all books” was not a reliable portfolio fact: KDP showed 76 processed units over 90 days, while the current month had zero processed orders but nonzero KENP reading. Radar must therefore ask which period, which format, and whether “sales” means units, reads, or royalties.

Future selection should use comparable post-live observation windows and must not treat a one-to-four-day zero as product failure. Before recommending price or metadata changes, Radar needs an availability check and a discovery/conversion denominator. If Amazon does not expose impressions, recommendations must be labeled as packaging hypotheses and tested one variable at a time.

No scoring weights were changed from this single pass. The reusable additions are the book-demand evidence field set, demand-window check, asset-after-demand rule, and authenticated KDP read-only audit contract.
